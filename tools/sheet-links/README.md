# Тарифы и оформление заявки из таблицы «Воронки ссылки»

Сверяет гугл-таблицу [«Воронки ссылки»][sheet] с блоками `tariffs`,
`applications` и `upsell` активных воронок базы и кладёт markdown-отчёт в
`data/generated/`.

Инструмент **ничего не пишет** — ни в базу, ни в таблицу. Решения по отчёту
принимает человек.

Дизайн: [docs/superpowers/specs/2026-08-17-sheet-links-design.md](../../docs/superpowers/specs/2026-08-17-sheet-links-design.md)

[sheet]: https://docs.google.com/spreadsheets/d/1TTFjAAwE2g0D0BUNyOcMkuybuhbqUHf3EirM4GU2xYI/edit

## Запуск

Из корня репозитория:

```sh
python3 tools/sheet-links/run_sheet_links.py
```

Флаги: `--db`, `--out`, `--cache`, `--today`, `--refresh`, `--plan`.

`--plan FILE` дополнительно выписывает раздел «Можно залить» в JSON для
скрипта заливки: воронка по F-коду, вид блока, режим и позиции. Правила
вывода режима и слота — в [links_plan.py](links_plan.py), там же замеры,
которые их обосновали. Смешанный блок (часть адресов со слотом, часть без)
в план не попадает, а печатается предупреждением.

Сам инструмент по-прежнему ничего не пишет ни в базу, ни в таблицу — план
это предложение, решение о записи принимает человек, а записывает отдельный
скрипт против **прода** (образец —
[app/scripts/archive/fill-sheet-links-prod-2026-08-18.cjs](../../app/scripts/archive/fill-sheet-links-prod-2026-08-18.cjs)).

`--cache FILE` кладёт сырой ответ таблицы в файл и при следующем прогоне
читает его вместо сети — удобно, пока правишь отчёт. Каждый раз, когда
прогон читает кеш вместо сети, консоль печатает возраст снимка — устаревший
снимок даёт уверенно неверную сверку, и об этом нельзя молчать.

`--refresh` игнорирует существующий кеш, идёт в сеть заново и перезаписывает
файл кеша свежим ответом — используется, когда таблицу правили и старый
снимок пора выбросить.

Тесты: `python3 -m pytest tools/sheet-links/tests`

## Что откуда берётся

Полная карта источника — какая колонка на каком листе, сколько в ней адресов
и во что она превращается — вынесена в
[docs/sheet-links-source-map.md](../../docs/sheet-links-source-map.md).
Начинать любую новую сборку ссылок из этой таблицы нужно с неё.

Коротко, что берёт этот инструмент сейчас:

| Колонка листа | Что | Куда |
|---|---|---|
| «ссылка на вебинар», «ссылка на повтор» | комнаты | ключ матчинга и слот |
| «продажная страница», хост `t.ksamata.ru` | тарифные страницы Tilda | блок «Тарифы» |
| «продажная страница», хост `gc.ksamata.ru` | та же колонка, дожимные адреса | блок «Допродажи / дожим» (`upsell`) |
| «страницы в ГК для тарифов» | `gc.ksamata.ru/…/tarif/…` | блок «Оформление заявки» |
| «посадочная страница» | подпись к соседней ссылке | справочно, в «Можно залить» |

**Колонки ищутся по названию, а не по номеру.** Раскладка различается: на
листе ТКМ продажная лежит в G (в F — «Ссылка на предсписок»), у Детокса и
Жизни тоже G, у ЗВ/ДББ/РД — H, а у шести листов колонки «страницы в ГК для
тарифов» нет вовсе и на её месте стоит ОТО. Прежняя жёсткая привязка была
верна для 19 листов из 26 и однажды увела предсписок ТКМ в допродажи —
до прода. Лист, на котором строку заголовков найти не удалось, печатается
предупреждением, а не читается наугад.

Колонка продажной страницы несёт два разных вида ссылок и различает их хост,
без единого исключения на живых листах (замер 17.08.2026): `t.ksamata.ru` —
только тарифы, `gc.ksamata.ru` — только допродажи/дожим (`upsell`, заголовок
«Допродажи / дожим», тот же вид блока, в который Phase 13 переименовала
`meditation`). Разделение по хосту, а не по слову в пути — `meditation-*`
только треть таких адресов, остальные названы по продукту.

Подпись из колонки «посадочная страница» не участвует в сравнении и не
пишется в базу — items базы подписей не несут. Печатается только рядом с
адресом в «Можно залить», когда непуста. В той же колонке встречаются и
адреса (235 против 789 подписей) — это лендинги и страницы «спасибо», их
сборка в блок `landings` ещё впереди.

## Блок листа — по началу строки, а не по её концу

Блок начинается там, где в колонке A или B значение **начинается** с `[`.
Хвост после скобки — норма (`[БОО сайт] НОВАЯ ЦЕНА`, `[ЖКТ Яндекс РСЯ] 4
времени`), встречается и опечатка с круглой скобкой. Хвост остаётся в имени:
«БОО сайт» и «БОО сайт НОВАЯ ЦЕНА» — два разных блока одного листа.

Признак именно «начинается со скобки», а не «содержит»: строки листа ЧО вида
`https://online.ksamata.ru/room/cho-tw1?[%web%]` скобки содержат, но
заголовками не являются.

Скрытые листы пропускаются. Блок считается мёртвым по маркерам «отключена»,
«комнаты удалены» в первых четырёх строках.

## Слот берётся у комнаты, а не у секции листа

Разметка времени в листах неровная: на строке «1 день» отметка стоит то в
колонке M, то в A, а в 244 случаях её нет вовсе. Значений времени в таблице
четыре (15:00, 19:00, 20:00, 17:00), а `funnel_days.time_slot` знает два.
Поэтому слот ссылки — это слот комнаты из её строки, каким его знает база.
Ссылки без якорной комнаты уходят в отдельный раздел отчёта — по строке
самой ссылки, а не по строке заголовка блока, чтобы владелец сразу видел,
куда идти в таблице.

## Сверять и заливать — против прода, не против базы репозитория

Репозиторная база отстаёт от прода (замер 18.08.2026: 9 блоков заполнены на
проде и пусты в репозитории). Отчёт по ней завышает заливаемое и прячет
расхождения. Поэтому прогон делается по снимку прода:

```sh
CONT=$(ssh server_ksamata_prod 'docker ps --format "{{.Names}}" | grep "^funnels-admin"')
ssh server_ksamata_prod "docker exec $CONT node -e \"const D=require('better-sqlite3');
  const db=new D(process.env.FUNNELS_DB_PATH,{readonly:true});
  db.exec(\\\"VACUUM INTO '/tmp/snap.db'\\\");db.close();\""
ssh server_ksamata_prod "docker exec $CONT cat /tmp/snap.db" > /tmp/prod.db
python3 tools/sheet-links/run_sheet_links.py --db /tmp/prod.db --plan /tmp/plan.json
```

Заливка — отдельным `.cjs` изнутри контейнера, через HTTP API прода.
Образцы в `app/scripts/archive/`: `fill-sheet-links-prod-2026-08-18.cjs`
заводит пустой блок, `fix-sheet-links-diffs-prod-2026-08-18.cjs` правит
существующий со сверкой `expect` до записи. Порядок всегда один — бэкап
`VACUUM INTO`, `--dry-run`, чтение вывода глазами, `--apply`.

## Имена модулей с префиксом `links_`

Все каталоги под `tools/` лежат в одном `sys.path`, импорты плоские, и при
совпадении имён побеждает импортированный первым — молча. Поэтому чтение базы
называется `links_db`, а не `db_source`, а настройки — `links_settings`.
