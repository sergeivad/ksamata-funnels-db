## Комплексный тест интерфейса (2026-07-19) — СДЕЛАНО

Три агента (гейты качества, API-прогон curl-ом на копии БД, код-ревью UI)
+ ручной прогон в песочнице (копия БД + отдельный dev-сервер, сохранения
разрешены). Итог: 0 пятисоток по API, 3 критичных + 9 заметных находок.

- [x] Критичное (потеря данных, отдельная сессия, `a54f79e`): переключатель
      «Общее/По времени» больше не автосохраняет и восстанавливает разбивку;
      тумблер «повтор» больше не стирает ссылки повторов при сохранении;
      dirty-гард распространён на router.push («Новая воронка»,
      «Дублировать», «← Список воронок»).
- [x] Заметное (`b85a0b5`): общий `copyText` с фолбэком через execCommand —
      копирование работает и по HTTP, ошибка видна красной вспышкой во всех
      6 местах; hover-иконки видимы на тач-устройствах и некликабельны, пока
      скрыты; редакторы комнат и by_time-блоков стекаются на мобильном
      (поля 55px → полная ширина); удаление в справочниках с подтверждением,
      ошибка добавления не съедает ввод; RefSelect и список воронок
      переживают сбой сети (кнопка «Повторить»); автоподстановка Web из GC
      не воскрешает намеренно стёртое; API: trim имён (пробельные → 400),
      строгий разбор id (`12abc` → 400); вставка с хвостовым \n из таблиц —
      одна строка.
- [ ] Мелочи из ревью не делались: вспышка «Скопировано» на не той строке
      при удалении строки в 1.5с-окне; flash режима Редактирование при
      открытии карточки в Просмотре; Switch не блокируется во время
      сохранения.

## Гигиена ссылок и счёт мониторинга (2026-07-25) — СДЕЛАНО

Разбор с дашборда мониторинга: почему в группе «Лендинги» проверялось 41 из 45
и почему рядом жила отдельная группа «Лендинг воронки».

- [x] Тесты мониторинга (`monitor-run`, `monitor-view`, `api-monitoring-route`)
      молча ждали пустую `monitor_targets` в скопированной фикстуре и краснели
      после любого локального дев-сервера. Общий хелпер
      `tests/helpers/monitoring.ts` чистит своё состояние в `beforeEach`
      (`7bfef61`).
- [x] Группа «Лендинг воронки» — не второй тип лендингов, а дрейф данных:
      URL лежал только в легаси-поле `funnels.landing_url` и не был заведён в
      блок «Лендинги» (воронки 5, 34, 36, 37, 38). Перенесены в блоки на проде;
      у №5 блок указывал на другой домен, отдававший 404.
- [x] 2026-08-04: группы больше нет вовсе. Поле `landing_url` и блок «Лендинги»
      дают один вид источника `landings` — страница воронки одна сущность, где
      бы её адрес ни лежал, а два чипа считали её дважды и хранили два разных
      решения «проверять или нет». Синк собирает оба места в одну группу,
      Phase-9 переводит то, что уже записано (при слиянии решений побеждает
      «выключено»).
- [x] Поле «Ссылка» больше не принимает затекшую подпись: значение,
      начинающееся с http(s), обязано быть чистой ссылкой (класс A — блокирует
      сохранение в редакторе и в PUT-роуте, рядом кнопка «Исправить»), а текст
      без http(s) (`сайты`, `геткурс`) только подсвечивается (класс B) —
      такие пометки живут в блоках годами и целей не создают
      (`app/src/lib/url-field.ts`, `4dac8a2`).
- [x] Данные прода: убрана хвостовая кавычка в ленде №16; шесть строк
      `сейлбот`/`сайты` в «Процессах» переехали в подпись `сейлбот — сайты`.
      Класс A на проде — ноль из 1356 ссылок.
- [x] Чип группы: оранжевый при любом числе включённых целей, а не только когда
      включены все — частичная группа больше не выглядит выключенной
      (`98782ac`).
- [x] Знаменатель чипа считает только страницы активных воронок. Архив (как и
      черновик) сам по себе означает, что страницы уходят из мониторинга;
      осиротевшие URL — тем более. В таблице у выключенной строки теперь видно,
      почему: «№16 · архив» или «больше не используется» (`f4525fe`, `4caef7c`).
- [ ] Осталось на подумать: чистка списанных целей (`monitor_targets` без
      воронок) старше N дней — сейчас они хранятся вечно ради истории
      инцидентов и видны только в «Показать выключенные».
